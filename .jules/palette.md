## 2025-06-11 - Adding Keyboard Accessibility to Alpine.js Action Cards
**Learning:** When using structural UI elements like `.welcome-action-card` `<div>`s in Alpine.js for interactive behaviors (`@click`), they must explicitly include `role="button"`, `tabindex="0"`, and keyboard event handlers (`@keydown.enter` and `@keydown.space.prevent`) to be accessible to keyboard and screen reader users. The application heavily relies on these custom div-based cards without inherent keyboard focusability.
**Action:** Always scan for `@click` handlers on non-native interactive elements (like `<div>` or `<span>`) across the codebase and ensure they are paired with appropriate ARIA roles, tabindex, and keydown listeners to guarantee WCAG compliance.
## 2024-09-24 - Accessibility fixes for chat navigation icons
**Learning:** Found instances where legacy `<span class="material-symbols-outlined">` were used inside `btn-icon-action` without `aria-hidden="true"`, causing screen readers to potentially announce raw icon ligatures. In addition, some `<button>` wrappers for those `<x-icon>` custom components were missing proper `aria-label` attributes.
**Action:** When updating accessibility for icon-only buttons that rely on Material Symbol ligatures or custom tags, always add an `aria-label` to the parent `<button>` and explicitly set `aria-hidden="true"` on the inner `<span>` to prevent screen readers from confusingly reading the raw ligature text. Better yet, migrate to the custom `<x-icon>` component that supports proper abstraction where possible, while adhering to the same a11y principles.
